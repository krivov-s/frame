## Реализация паттерна Clean Architecture в ядре

### 1. Уровень Domain (проект Frame.Domain)

#### На уровене Domain реализуются:

- Сущности (объекты) системы (Entities)
- Интерфейсы объектных репозиториев, которы должны быть реализованы на уровне Infrastructure
- Главные бинес-правила, которые зависят только от сущностей  

__ВАЖНО!__
```
Для корректной работы логики, заключенной в уровне Domain необходимо обеспечить полное считывание всех связанных объектов!
За это отвечает типизированный (или корректно настроенный универсальный) репозиторий или EntityLoader!
Важно быть уверенным, что когда разработчик получает из репозитория или Loader-а объект, в него загружены все данные, необходимые для работы!
```
### 2. Уровень Application (проект Frame.App)

#### На уровне Application реализуются:

- Создание, удаление, изменение сущностей, включая групповое, учет взаимозависимостей сущностей,
  вызов интерфейсов объектных репозиториев
- Бизнес-логика работы с сущностями
- Варианты использования: поток данных в сущности и обратно

#### Структура папок внутри проекта Frame.App
- Cores - объекты и интерфейсы ядра системы (UserCore, ServerCore, AppCore)
- Security - служебные объекты ядра связанные с безопасностью и правами доступа
- IEntityLoaders - интерфейсы объектов - загрузчиков моделей из БД. _скорее всего почти не будет использоваться в проекте, предпочтение - репозиториям_
- IEntityRepositories - интерфейсы объектов - репозиториев моделей. Сами объекты, реализующие данные интерфейсы, содержатся на уровне Infrastructure. Связывание осуществляется через DependencyInjection.
- В корне проекта файл DependencyInjection.cs - связывание интерфейсов и их реализаций. На уровне Application в данном случае связываются только интерфейсы и реализации IUserCore и IServerCore
- В корне проекта файл IFilesRepository.cs - интерфейс файлового хранилища.

### 3. Уровень Infrastructure (проект Frame.Infrastructure)

#### На уровне Infrastructure реализуются:

- DBContext _(в нашем случае AppDbContext и NoSecurityDbContext)_
- Реализация методов объектных репоиториев, чтения/записи из/в БД. _(в нашем случае общий EFBaseRepository<> и частные репозитории)_   
  Например, когда логика с уровня Application вызовет IBaseRepository.UpdateAsync, именно сюда должен прийти этот вызов и произойти фиическое сохранение объекта.

#### Структура папок внутри проекта Frame.Infrastructure
- DBContext - реализация DBContext. В дополнение к стандартному DBContext реализуются дополнительные методы, связанные с ограничением прав доступа.
- EntityDbConfigurations - объекты, реализующие интерфейс IEntityTypeConfiguration. Цель - вынесение в отдельные объекты настройки базы данных для моделей, которым не достаточно базовых настроек по-умолчанию, в соответствии с правилами EF.Core.
    - Внутренняя структура папок должна соответствовать структуре папок Frame.Domain/Entities.
- EntityLoaders - реализация интерфейсов, объявленных в Frame.App/IEntityLoaders
- EntityRepositories - реализация интерфейсов, объявленных в Frame.App/IEntityRepositories
- EventBus - реализация очереди в памяти (теоретически может быть заменена на RabbitMQ, Redis и т.п.)
- Logger - реализация логгера для всего проекта.
- S3Repository - реализация интерфейса IFilesRepository, объявленного на уровне Frame.App репозитория файлового хранилища, для корпоративного Yandex S3.
- Security - классы, отвечающие за безопасность и распределение прав доступа
- В корне проекта файл DependencyInjection.cs - связывание интерфейсов и их реализаций. 
  __Максимально интенсивное использование!__ Почти все связи между интерфейсами и объектами настраиваются здесь. 
  Все репозитории объявляются и настраиваются тоже здесь.

## Exceptions
- В проекте Domain.Shared реализован класс Класс BusinessApp.Shared.Result<T>. Используем его везде для минимизации выбросов Exceptions
Исходим из того, что Exception - это исключительная, неожиданная ситуация, которая должна обрабатываться глобально.
Все ожидаемые ошибки нужно обрабатывать через Result и дублировать (при необходимости) в логе. 
( Источник - модель обработки возвратов из контроллеров: https://dev.to/sam_ferree/avoiding-exceptions-in-aspnet-core-lb4)


## Репозитории
- В проекте Frame.Infrastructure реализован универсальный репозиторий
```csharp
class EFBaseRepository<TEntity> : IBaseRepository<TEntity>
```
По-умолчанию зачитывает линейные атрибуты заданного типа без фильтрации.
Также есть 
```csharp
class EFBaseRepositoryProvider : IBaseRepositoryProvider
```
который можно использовать для получения новых репозиториев заданного типа. Базовый репозиторий расширяется и донастраивается путем наследования и регистрации в конвейере DI нового класса.
Настраивать секции Select и Where без наследования можно с использованием EFBaseRepositoryOptions путем регистрации типизированного репозитория 
вызовом 
```csharp
services.AddBaseRepository(options => {})
```
